# Independent review of Claude’s Line Expansion fix

**Hold the merge of `d0a9b01`.** Claude’s 40 regression cases pass. Two additional end-to-end checks found that an ordinary sections-only output fails in Assembly and that importing a rotated body with missing attitude metadata can silently give the wrong complex field. Imported-grid admission, legacy field metadata and cancellation also need corrections. The results below distinguish behavior already present on main from regressions where an A/B comparison was run. [Claude’s fix note](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/audits/claude-2026-11-26/astra-audit-response/LINE_EXPANSION_FIX.md)

## Findings for the next patch

1. **Assembly rejects sections-only output, even with an STL.** I ran the public preview, preparation and execution functions on a freshly exported section, both alone and with an explicit triangular STL. On `ed90b65` both runs finished and all six reopened complex samples equaled the input. On the candidate all four attempts to preview or prepare failed with “body GRIM has no embedded profile.” Every expanded file now declares its radar grid. Assembly uses the presence of that grid to choose the embedded BoR geometry path. Keep the attitude record and select the geometry source independently in preview, preparation and execution. As a positive control, a real BoR body with an embedded profile passed all three steps and preserved all 72 complex samples exactly. [Producer](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L932) · [Preview](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/workflow.py#L1069) · [Preparation](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/workflow.py#L3913)

2. **A missing body attitude is silently promoted to a recorded zero.** I exported a real BoR sphere at body-axis azimuth 20°, elevation −10°, roll 15°, and separately computed a section at that orientation. With the intact base, the reopened sum equaled the reference exactly. GRIM’s Axis Edit changed a 0° look to its equivalent 360° and reordered the grid. Saving preserved every field value and the body profile but dropped the radar-grid request. Adding the same section implicitly then gave **56.04% peak-normalized complex-field error**, issued no warning, and recorded zero for all three angles. The implicit error also occurs on main. Supplying the known correct orientation on main restored agreement to `2.15e-16`. The candidate newly refuses that correction. Removing only the optional request from a separate real export reproduced the same failure. The shared reader synthesizes zero when it recovers axes from the body, and the conflict check treats those fallback numbers as measurements. Track which attitude values are actually declared. Preserve genuinely known values, accept an explicit value for an unknown angle, and make any implicit assumption visible. Apply this rule to missing or invalid requests and check physical equivalence when comparing declared angles. The current check also rejects the equivalent azimuths 20° and 380°. The GUI presently has no way to enter a missing attitude. [Reader](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/fields.py#L1975) · [Conflict check](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L682)

3. **A supported power-and-phase base produces a file that cannot be expanded again.** A version-1 file written by the repository’s own writer carried linear power and phase, with no optional complex-field-domain tag. The first expanded field matched the expected sum to `1.33e-16`, but the job saved it as `solver_raw_far_field_amplitude`. The next Line Expansion run rejected the saved file on both main and the candidate. This is a remaining compatibility defect. The coherent-field validator supplies canonical metadata and records assumptions on a working copy. Its result is discarded, leaving the writer to choose its generic fallback. Carry the validated radar-frame domain and relevant advisories into the output, then test a second real expansion. Keep the existing rejection of explicitly contradictory input. [Validator call](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L212) · [Writer default](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/io/grim.py#L842)

4. **An oversized imported base is read and decoded before the grid check.** With a six-look native file and a test ceiling of five looks, the importer read all 23 archive members, including the complex field, before rejecting it. The same six looks entered directly were rejected before reading any field. This defeats the intended memory protection for large imports. Inspect the stored axis and sample shapes before reading bulk arrays, and account for every channel retained in the result. A five-channel input was accepted and wrote 30 complex samples under a scaled 24-sample ceiling. The 100,000 per-axis limit is also specific to the GUI parser, where a near-integral endpoint can still yield 100,001. Test the actual counts at the boundary. These runs establish read order and dimensions. Actual peak RAM near the unscaled ceilings was not measured. [Import](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L523) · [Grid check](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L667) · [GUI parser](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/ui/line_expansion.py#L54)

5. **Independent API cancellation signals can be lost.** An existing caller can supply a section-solver abort event and a separate application callback. With the event set and the callback false, main stopped and kept the existing file. The candidate overwrote the section event, completed, and replaced the file. The new top-level event is also ignored during publication when a separate callback returns false. Preserve an abort request from any supported source and test it both inside the section solver and at publication. The ordinary GUI uses one event and passed its cancellation check. [Cancellation setup](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L624)

6. **Two same-process exports to one destination can publish the canceled job’s file.** A deterministic schedule ran two real API exports. Job A requested 30° and reported success. Job B requested 60° and reported cancellation. The file reopened at **60°**. Both jobs stage to a filename derived from the destination and process ID. This collision also reproduces on main. Give each job a unique staging file in the destination directory and clean up only that file. Separately, a real GUI click between the final cancellation poll and the rename showed the assurance that the previous file would be kept, then reported Saved and replaced it. Coordinate the accepted-cancel boundary with entry into publication and reflect that state in the UI. Both schedules were forced to test guarantees. Their frequency in ordinary use is unknown. [Staging](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L805) · [Publication](https://github.com/14cole/20261028_GRIM/blob/d0a9b010eb821df95a30b41be2fc8605ca90d90e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L939)

## Checks that passed

- Reran Claude’s unchanged 40-case suite and its independent numerical, offscreen GUI and BoR export scripts. The default shadowed BoR case gave zero added field on all four fully hidden looks. The largest relative difference on 18 clear looks was `5.39e-16`. Re-expanding this correctly tagged file gave `1.64e-16` error against the two-addition reference. Errors use maximum absolute complex-field difference divided by peak reference magnitude, except the clear-look check, which uses peak unshadowed section magnitude.
- Cancellation during the normal GUI section solve returned to idle at 0.53 s after a click at 0.50 s, compared with 3.15 s for the uninterrupted run. No new output appeared. Canceling immediately after the staging write returned also preserved the old bytes and removed the staging file. These timings are individual observations.
- A manually specified grid of 35,901 azimuths by 18,001 elevations (646,253,901 looks) was refused before the first product-array construction. The small control wrote a real output. The separate imported-base experiment above exercises a different entry path.
- The four changed production files are confined to Line Expansion, shared visibility and the GRIM writer. The retired Line Expansion patch is gone. The cgroup trial remains an audit attachment and is unapplied. The Linux memory-admission work, packaging and native diagnostics, and the native Windows distribution run remain open from the previous handoff. This review exercised Linux x86-64 with offscreen Qt.
