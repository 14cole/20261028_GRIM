## Linux memory, packaging, and release

- Claude’s scheduler correction holds. With 32 GiB synthetic host RAM the current scheduler ignores a mount-root limit at 511 and 512 MiB, and honors 513 and 768 MiB. The exact 512 MiB result is a threshold issue. Nested hierarchy discovery is a separate defect. Release can over-admit or under-admit: mounting an unrelated sibling at the conventional root gave 0.1125 GiB of budget instead of 3.6 GiB in the tested layout.
- Specify separate expected values for scheduler **capacity**, solver **available memory**, and the **admitted budget**. At a readable 768 MiB cap and 256 MiB used these are 0.75, 0.50 and 0.45 GiB. With unreadable group usage, two systems can expose identical counters and process RSS while having different true headroom. Choose and document a conservative fallback or explicit uncertainty there. A test cannot require exact remaining bytes from unavailable information.

I accept Claude’s suggestion to remove the unused dataclasses backport notice together with its HPC snapshot-list entry as part of packaging cleanup. The backport was removed in `43b92b0`. Keep the native diagnostic usable from the intended install format. Verify each distributed native binary against that artifact's identity and exports and distinguish unavailable acceleration from a path a particular solve actually used. This review did not repeat the previous package builds or Claude’s damaged-library runs.
