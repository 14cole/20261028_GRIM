# Round-two Line Expansion review

**Hold the merge of `9635f7c`.** I reproduced Claude’s 55 passing tests and the fixes for the original fixtures. GRIM’s Assembly panel still rejects a freshly expanded sections-only file. Bypassing the panel exposes a second problem: Assembly can add a feature at zero body attitude and save the result labeled with the base’s nonzero attitude. A third workflow loses a known orientation when an already expanded file passes through GRIM’s Axis Edit. These are observable through ordinary application operations. [Claude’s reply and test instructions](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/audits/claude-2026-11-26/astra-audit-response/LINE_EXPANSION_FIX_ROUND2.md)

## Fix before merging

**1. The GRIM Assembly panel classifies a sections-only output as malformed.** I selected a fresh Line Expansion output in the actual offscreen Qt panel with a working backend, a destination, and, in the second run, a valid STL and its units. Both showed “Malformed embedded BoR metadata; requested radar grid has no body profile.” Both Validate and Calculate were disabled. The same selections on main enabled both actions. An expanded genuine BoR file was accepted in both builds. Round two fixed the GHOST workflow’s no-feature case, but GRIM has a separate file classifier still equating a radar-grid request with embedded geometry. Align the panel and backend on the geometry-source decision while continuing to reject an incomplete profile pair. [GUI classifier](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/GRIM_Backend/assembly/model.py#L1009) · [Panel readiness](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/GRIM_Backend/assembly/panel.py#L3277)

**2. Assembly ignores a rotated sections-only base’s declared attitude when it adds a feature.** A real preview, plan and execution placed a point with a known response on an STL for a sections-only base at (20°, −10°, 15°). The plan used (0°, 0°, 0°). The combined file retained the input’s nonzero attitude. Comparing the reopened result with the independently calculated complex field gave **156.93% error in the added feature and 138.24% in the total**. The added field agreed with the zero-attitude calculation to `1.10e-15`. A zero-attitude sections-only control and a rotated expanded BoR control agreed with their intended references to within `1.15e-15`.

With the default one-sided point setting, the first case still gave **146.13% added-feature error and 128.73% total-field error**. A second orientation, (−35°, 23°, 42°), on a different look grid gave 196.82% feature error. Changing only the external plan’s three default angles in a diagnostic process reduced it to `1.27e-15`. Main already had the zero-default numerical behavior and did not record the sections-only attitude. Round one refused this file outright. Round two now has the correct declaration available and carries it into the output without using it for the calculation. Keep geometry-source selection separate from attitude selection. Read the base’s valid orientation for the plan and write the effective orientation to the result. Test the added field as well as the total. [Geometry routing](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/fields.py#L1982) · [Plan defaults](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/workflow.py#L3935)

**3. Axis Edit can discard a known attitude even when the samples and their physical directions are unchanged.** I started with a sections-only file explicitly expanded at (20°, −10°, 15°), relabeled the 0° look as 360° through Axis Edit, saved it and reopened it. All samples matched exactly after reordering. The request was gone, but the expansion provenance still held all three angles and marked them as stated. The next expansion ignored that record. Blank inputs gave a warning and **43.82% field error**. Contradictory inputs were accepted without warning and gave **69.13% error**. Restating the original orientation gave `1.98e-16` error. This differs from Claude’s original BoR fixture, whose missing request left genuinely unknown values. Preserve the effective attitude on a pure reindex or equivalent-angle relabel. Reconcile it with expansion provenance when the coordinate frame is demonstrably the same. A real change of frame requires separate handling. [Axis Edit](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/GRIM_Backend/datasets/axes.py#L345) · [Attitude reader](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L233)

## Two narrower corrections

- **Legacy field metadata.** The ordinary power-and-phase round trip is numerically correct. When the version-1 writer represents missing phase and amplitude declarations as empty strings and there is already a metadata advisory, the two saved declarations stay blank and the validator’s new advisories are lost. Two ordinary expansions agreed with the expected fields to within `1.78e-16`, but strict Assembly rejected the new output for the two missing declarations. The fully declared control passed strict Assembly exactly. Treat empty declarations as missing, merge existing and new advisories, and preserve the distinction between assumed and supplied conventions. [Copy-back logic](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L287)
- **Cancellation through the public API.** A caller supplied both an abort event and a separate bound callback on that controller. The callback returned true when called, but the code skipped it entirely and saved over the previous output. The same method wrapped in a lambda canceled, as did the bound method on round one. A second case delivered a one-shot cancel at the final gate. The gate declined publication, the immediate second poll saw false, and the rename still replaced the file. In-memory trials deduplicating only the same `is_set` method and stopping unconditionally when the gate declines fixed both cases. An ordinary GUI click, two simultaneous jobs and a simulated failed rename all behaved correctly on the candidate. [Combining signals](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L719) · [Final gate](https://github.com/14cole/20261028_GRIM/blob/9635f7c2e67b7b4f639997a524e77558a069bb6e/tools/GHOST/ghost_backend/assembly/expand_wing_sections.py#L1069)

## Results that hold

| Check | Independent result |
|---|---|
| Claude’s unchanged 55 tests | 55 passed on round two. Running the same suite on round one gave 43 passes and 12 failures, as reported. |
| Three unchanged standalone scripts | Numerical, GUI and BoR results agreed with Claude’s saved results within tolerance after accounting for timing and temporary paths. Four hidden looks had zero added field. Across 18 clear looks the maximum error was `5.39e-16`. A no-feature Assembly pass preserved all 72 BoR samples exactly. |
| Original missing-request and GUI cases | The real BoR case with its request removed warned when left blank. Stating the known attitude produced the expected field. The GUI’s three optional fields also worked. A blank attitude on its rotated fixture gave a warning and 53.46% error, and filling it in gave zero error. Equivalent 20° and 380° azimuth inputs were accepted. |
| Grid admission on conforming inputs | Twelve v1/v2 and boundary cases passed. Oversized native imports read only the four axes before refusal and preserved the old output. At the exact limit, both native formats produced the expected field. A five-channel file required all 30 sample slots. The unchanged 646,253,901-look probe was refused before meshgrid. Peak RAM at the actual ceilings remains unmeasured, and malformed field shapes are validated after reading the field. |
| Ordinary cancellation and publication | The GUI returned to idle with no output, independent latched events canceled, and the simultaneous A/B test published only the successful 30° job’s file. A click after publication began received the late-cancel message. |

All relative field errors above are maximum absolute complex-field differences divided by the peak magnitude of the indicated reference. Line Expansion and Assembly were exercised with production writers and readers on Linux x86-64, using Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0 and PySide6 6.12.0. The 528 tracked files outside the audit tree matched GitHub blob identities at the reviewed commit. Windows packaging, native diagnostics and the separate Linux memory-admission change remain outside this review.
