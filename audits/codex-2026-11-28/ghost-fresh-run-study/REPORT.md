# GHOST solver efficiency from geometry input to exported fields

**Recommendation. Keep the text geometry format, Automatic mesh search and both 2D linear backends. Make fresh solves more efficient.** The best immediate investments are correcting the mesh estimator, reading the active run's results once for display, and eliminating specific duplicate allocations. Dense and Compressed encounter different bottlenecks on the same airfoil. A single solver, a new file format or a machine-specific history database would add complexity without addressing those costs.

Every proposed production workflow starts from the user's geometry and material inputs. All suggested reuse is local to the current job or its open result and can be released with it. The research branch contains evidence and proposals. It introduces no changes to the distributed application.

## What the shipped solver actually cost

The main reference is `95f87190956de9197f0d021b0497772818c6f532`. All 528 tracked blobs in the checkout matched GitHub. We used the 350-edge, 19-segment repository airfoil in inches, its original PEC and dielectric definitions, both polarizations and Standard mesh convergence. Independent processes ran the same numerical entry points, recovery records and final GRIM writer used by the GUI. Times include file read, capture, computation, saving completed frequencies and final export. Application startup, the optional desktop planning display, plot rendering and model verification are outside these timers. The runs used two solver threads and one frequency at a time, on a shared Linux AMD EPYC host with a four-core quota and 16 GiB memory limit. RSS is the process high-water mark. These are machine-specific results. [Source geometry](https://github.com/14cole/20261028_GRIM/blob/95f87190956de9197f0d021b0497772818c6f532/airfoil.geo)

| Airfoil run | Monostatic angles | Linear backend | Accepted panels / unknowns per polarization | Time through export | Peak process RSS |
|---|---:|---|---:|---:|---:|
| 1 GHz | 180 | Automatic chose Dense | 414 / 1,936 | 6.82 s median, 3 runs | 0.36–0.38 GiB |
| 5 GHz | 360 | Automatic chose Dense | 1,334 / 6,100 | 47.07–49.74 s, 2 runs | 2.01–2.03 GiB |
| 5 GHz | 360 | Forced Compressed | 1,334 / 6,100 | 55.05–57.24 s, 2 runs | 0.75–0.77 GiB |
| 10 GHz | 180 | Automatic chose Compressed | 2,502 / 11,434 | 88.12 s, 1 run | 1.18 GiB |
| 15 GHz | 180 | Automatic chose Compressed | 3,744 / 17,086 | 164.65 s, 1 run | 1.68 GiB |

All five cases passed the existing field-quality and mesh-convergence checks. The 5 GHz comparison used the same mesh workflow, geometry, ordered angle grid and tolerances. The maximum complex-field difference between backends, divided by the corresponding polarization's peak, was 2.10e−12 across all 720 values. On this mesh, Dense finished sooner and Compressed freed about 1.25 GiB of peak process memory. The 10 and 15 GHz timings use half as many angles as the 5 GHz timings, so they are not a frequency scaling law.

At 1 GHz the actual text read and parse took around 1–2 ms. In an isolated 5 GHz specified-mesh test, parsing and constructing the snapshot together took about 0.7 ms, validating it took 18 ms, and constructing the 9,448 P1 panels and TE topology took about 384 ms. Converting the user's files to binary would save little on this workload. A useful internal cleanup is to pass the existing mesh elements directly to the material mapper. It currently constructs a second temporary panel per element. Removing that conversion saved 13 ms and 1.66 MiB of peak Python allocations in one 5 GHz call. Every material record matched in both polarizations on the airfoil and all 15 shipped material examples, including tapers, thin layers and CSV inputs. Those are call-level benefits. [Material mapper adapter](https://github.com/14cole/20261028_GRIM/blob/95f87190956de9197f0d021b0497772818c6f532/tools/GHOST/ghost_backend/twod/solver.py#L428)

**Why keep both backends.** At 5 GHz the largest certified system had 6,100 unknowns. On the first Dense run, factorization took 19.1 s, operator work 9.2 s and the linear-solve stage 11.0 s. On the first forced Compressed run, compressed assembly took 38.2 s and factorization took 5.4 s. At 15 GHz Automatic used Compressed, with 109.2 s in compressed assembly, 16.6 s in factorization and 15.2 s in condition estimation. The internal stages can nest or overlap. They identify where to work and cannot be summed into an independent timing breakdown. Assembly is the first high-frequency Compressed target on this airfoil. Dropping convergence or condition checks to improve that number would remove part of the result users rely on.

The open-result display and region-membership changes address two different problems. The first removes a visible wait after a wide sweep. The second reduces transient working memory on many-body models. Neither requires a previous result on the machine.

## A geometry change that can pay off without changing the input format

**Make Local sizing recognize a smooth, physically identical contour across segment headers.** The current guard can apply the shortest global wavelength to an entire named segment when its bounding box is near another segment. On the shipped airfoil, five of nineteen segments had a longer material-only wavelength and none retained it after protection. Local and Global P1 consequently produced identical counts at all four frequencies. That finding alone does not establish that relaxing the guard on this tightly coupled airfoil is accurate.

We built a separate 5 GHz control: a smooth, 64-sided PEC cylinder and a 64-sided dielectric cylinder 1.5 m away. Geometry units were meters. Both files have the same ordered coordinate hash, materials and 20-panels-per-wavelength setting. We changed only whether the PEC contour was organized as one named segment or two. The feature detector found no corners, open ends or junctions requiring extra protection on these inputs.

| 180 angles, both polarizations | One named PEC segment | Two named PEC segments |
|---|---:|---:|
| Local specified mesh, base panels | 704 | 1,344 |
| Check specified mesh, published panels | 1,056 | 2,016 |
| Published unknowns per polarization | 1,728 | 2,688 |
| Checked elapsed time through export, median of three trials | 4.75 s | 10.73 s |
| Checked peak process RSS, range | 318–320 MiB | 484–484 MiB |

Both checked workflows passed at the same Standard target. The largest difference between their full published complex fields was **0.000204% of the corresponding peak**. The comparison quantifies mesh agreement for this fixture. An independent analytical reference for these interacting bodies remains open. Global P1 produced 1,344 base panels under either grouping.

This is a promising *fresh-solve* numerical improvement. Preserve named segments in the editor and exported file. For meshing, recognize a smooth continuation with identical material and boundary data, then apply proximity protection locally to the relevant edges. Start with PEC curves like this fixture. Before generalizing, repeat with close gaps, real material transitions, tapered sheets, acute corners, dispersive media and deliberate near-junctions. Compare all angles with a denser independent mesh or an analytical reference. Keep conservative sizing whenever physical equivalence is ambiguous.

## Mesh choice, geometry fidelity and run setup

- Keep **Find converged mesh automatically** as the starting point. Keep **Solve specified mesh** under Advanced for an externally validated mesh. Show what the current request means in the GUI: input units and extents, initial mesh/order/DOFs per polarization, Dense/Compressed memory estimates, scratch requirement and selected backend. Mark adaptive candidate counts as provisional. The user can act on these numbers before launching a job.
- Keep geometry representation accuracy visible. GHOST subdivides the supplied straight edges. Refinement cannot recover curvature missing from an imported contour. In a previous independent 6 GHz coated-cylinder check, a 16/12-side input passed mesh convergence yet had a TE complex-field error of 111.8% against the ideal cylinder. A 360/288-side input reduced it to 0.149%. Show “mesh convergence on supplied geometry,” and retain source-curve tessellation tolerance if a future importer knows it. Never infer the intended curvature from arbitrary straight edges. [Independent cylinder check](https://github.com/14cole/20261028_GRIM/blob/620fb9ebc1c5b2248687ecbf4841ca633904b700/audits/claude-2026-11-26/ghost-backend-audit/REVIEW.md)
- Preserve existing material checks and the in-run snapshot. The tests found that a content-equivalent snapshot reused validation, changed subdivision input was checked, a CSV edit was detected by fingerprint verification, and a fresh run saw the new material. An immutable internal representation is useful if it cuts repeated array/header construction. The measured parse cost puts a binary or on-disk geometry database low on the list.
- Bound sweep planning by active work. In a small PEC fixture, the 16 MiB in-run forecast cache retained all 261 frequency entries. At 521 frequencies it retained 505. Two ordinary forward passes got zero second-pass hits and spent about 10 s each. A compact plan per pending frequency or bounded handoff from preflight to dispatch can avoid the repeat. A small trial that visited the most recently planned frequencies first recovered 505/521 hits and preserved all 521 final queue positions, costs and backend choices. Recheck live RAM and candidate validity at execution. Keep existing cold-start behavior and use an explicit size cap.
- In a controlled resource test, one unfittable point in a three-frequency request blocked the complete desktop sweep. The worker planner could admit the other two. A per-frequency setup table would explain this and let users explicitly select the frequencies that fit. Leave a complete sweep as the default, list omitted frequencies, and never publish an incomplete set as complete.

## RAM on a 32 GB desktop

The user's geometry choice can matter more than any storage optimization here. For the 15 GHz airfoil with the file's global P1 recipe, one 42,592 × 42,592 double-complex dense matrix alone occupies **27.03 GiB**. That excludes LU workspace, RHSs, other arrays, the app and the OS. The Automatic mesh's largest initial candidate was 17,086 unknowns. On the Linux setup its 180-angle certified run actually finished at a process peak of 1.68 GiB using Compressed.

The following figures are **planner estimates**, using the stock 360-angle input and scratch availability on the test host. Certified estimates cover its initial candidates. Different scratch availability can trade process RAM for I/O. One effective CPU was available to this particular planning probe. These are not Windows capacity guarantees.

| Airfoil frequency | Automatic mesh Dense / Compressed GiB | Specified P1 Dense / Compressed GiB |
|---|---:|---:|
| 1 GHz | 0.84 / 0.62 | 0.70 / 0.49 |
| 5 GHz | 1.93 / 1.35 | 7.08 / 2.35 |
| 10 GHz | 4.96 / 2.58 | 25.74 / 5.81 |
| 15 GHz | 10.02 / 4.16 | 56.30 / 10.25 |

**Dense under pressure already has a strong experimental candidate.** In a previous same-host, full 360-angle Linux run at 23,936 unknowns, correctly accounting for the resident second-polarization matrix during admission reduced disk reads from 6,316 to 72.6 GB and wall time from 2,533 to 777 s. Peak process RSS increased from 9.45 to 9.54 GiB. This was a batch-width and I/O correction. It is independent of past runs. Before shipping, verify it on native 32 GB Windows under pressure and with ample RAM, including actual private commit, physical memory, scratch bytes/read traffic, batch widths, residuals and both full complex fields. Windows binaries being present does not validate Windows memory accounting. ## Larger numerical research worth pursuing

**Compressed source-side basis sharing.** Production already shares part of each far interaction on the receiver side. We found additional redundancy among interactions with a common source interval. On a PEC circle, an asymmetric PEC star and a dielectric-coated PEC circle at 10 GHz and 180 incident angles, the additional representation required **3.94–14.86% fewer bytes for one retained operator**, depending on geometry and polarization. On the coated case, the two polarizations saved 14.58% and 14.86%. We substituted the projected coefficients into the existing-sized buffers and solved the physical problems. Worst coated field drift was 5.77e−11 relative to the peak. The independent analytical field error was about 0.0194% or less. A tougher held-out TM equation check worsened from 2.29e−12 to 1.47e−11. Global field agreement alone would miss that change.

The old and new buffers coexisted in this experiment. A streaming constructor must demonstrate lower *peak private/process memory* and acceptable assembly time on successful larger models before this becomes a product feature. Check forward/transpose/adjoint products, held-out rows with actual solved densities, full signed-angle complex fields and the same mesh and condition gates. Close the experiment if the new constructor just moves the peak into factorization or its error budget fails. The percentage applies to operator storage, not total workstation RAM.

**Junction quadrature and interface pooling.** A bounded prototype grouped straight segments using the existing endpoint and adaptive subdivision rules for positive real wavenumbers. On six 600-segment quadrature probes (P1–P3, 1 and 15 GHz), the isolated kernel was 1.4–3.7× faster. The largest absolute coefficient difference was 1.05e−15. On three full 1 GHz airfoil trials, median solve plus recovery was 6.68 s shipped and 6.38 s grouped; ranges overlapped. The two polarization fields agreed within 4.7e−15 of peak. A second prototype pooled constant interface records and removed temporary panels. It produced identical exported fields but took 6.80 s median. Prefer the small direct-element cleanup above. Revisit batched quadrature on junction-heavy models if profiling shows it matters; there is no reliable general end-to-end speed claim.

**Alternatives with narrower applicability.** Prior work at 32,768 unknowns and 180 actual monostatic incidences measured FMM at 3,944 s / 1.71 GiB and Compressed at 416 s / 3.71 GiB on one dielectric-star geometry. That is a real RAM trade for about 9.5× longer elapsed time. A separate 8,000-unknown factor-only trial put Dense LU on disk: 2.04 → 0.32 GiB RSS but 18.8 → 149.8 s. Those are fallbacks for jobs that otherwise cannot fit. Rotational symmetry may accelerate bodies with exactly matching mesh, materials and orientation. It needs eligibility checks before reduction, and a generic path for asymmetric geometry. Earlier mixed-precision inverse tests delivered little whole-job benefit. GPU offload, arbitrary frequency interpolation and a new input format have no new supporting benchmark in this investigation. Preserve the exact requested angles and frequencies by default. ## Bodies of revolution, native libraries and distribution

BoR uses an independent modal solver. On a PEC sphere with 181 aspects, native streaming took 2.91–3.21 s, the native tables 3.17 s and NumPy fallback 13.40 s. Both polarizations agreed with the analytical Mie solution within 0.022 dB on all paths. A lossy dielectric sphere agreed within 0.040 dB and instrumentation confirmed that the native grouped sampler handled its complex interior wavenumber. The short GHOST README misdescribes that case, and the geometry entry point omits the available per-medium sampler names. Fix the description and expose the selected path in run diagnostics.

All four DLLs and four Linux shared objects matched their manifests. All four Linux libraries loaded with the expected exports. The provided speed-path check nonetheless reported seven OK entries with the 2D near kernel forced unavailable. Check that kernel and required entry points explicitly. Native Windows loader behavior and performance, large layered BoR models, a complete 20-foot model on a 32 GB desktop and an HPC cluster run were outside this test environment.

## Implementation order and independent review

1. Ship narrowly scoped corrections after regression tests: TE topology in desktop/HPC planning, native-path diagnostics, and one-pass preparation of the active desktop result. Validate correct reports and interactive behavior on both desktop platforms.
2. Land the direct-element cleanup, signed dielectric RHS reuse and shared regional membership independently. Compare complete fields, the maximum live allocations during the affected stages, and the whole-job peak. Add the bistatic column writer for users of incidence-by-observation grids.
3. Test physical-feature-based Local sizing next, starting with smooth same-material contours and then harder interacting geometries. Keep the Windows Dense pressure qualification and a bounded Compressed source-basis constructor as separate experiments. Publish a success or stop decision based on complete-job time, RAM and accuracy. The current default remains appropriate.

For an independent review, first reproduce the TE sheet fixtures and construct a new connected-sheet counterexample. Then exercise the display path with different axis orders, an interrupted sweep and a deliberately damaged frequency record. For numerical review, choose a new asymmetric many-material geometry and a known analytical control; compare held-out rows and full complex fields, and record RSS/private memory, backend, factorization count, scratch traffic and elapsed time.
