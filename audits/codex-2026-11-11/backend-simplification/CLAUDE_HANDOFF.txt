Purpose and measured scope
--------------------------
Reduce duplicated driver control flow and make independent BoR responsibilities
reviewable without changing numerical methods or removing supported solve paths.

14 changed files: 1,380 insertions, 1,418 deletions, 38 net lines removed.
Five new modules organize code that still serves an active purpose. This is
primarily a structural simplification, not a large reduction in backend size:

  bor/solver.py                 7,460 -> 6,896 lines
  runs/local_twod_driver.py       732 ->   630
  runs/local_bor_driver.py        944 ->   843
  hpc/twod_driver.py            1,246 -> 1,169
  hpc/bor_driver.py             1,504 -> 1,443

The four drivers shrink by 341 lines together. Extracting definitions accounts
for most of the main BoR solver's 564-line reduction. No speed or RAM reduction
is claimed. Reference-run timings are incidental measurements under concurrent
validation load; do not interpret their differences as a performance benchmark.

Implementation
--------------
1. Shared solve/export pipelines in runs/worker_pipeline.py.

   Local and HPC 2D workers use run_twod_unit. Local and HPC BoR workers use
   run_bor_pair and solve_bor_result. WorkerAdapter passes explicit callbacks
   for output paths, source/input checks, attestation construction, loading,
   history labels and memory evidence. The remaining driver wrappers preserve
   the existing pool entry points and parameter lists used by their callers.

   Kept transport-specific policies: HPC paths versus local results folders,
   frozen-manifest loading, per-pair HPC BoR execution-plan overrides, local BoR
   duplicate-input-check suppression, publication history strings, CPU/RAM
   scopes and pool cleanup. Both source and input checks still run before reuse
   and again after solving, before output publication. Partial BoR restarts
   co-solve the pair but publish only missing channel artifacts.

   runs/inputs.py now shares normalized-context attestation construction across
   local 2D, HPC 2D and local BoR, plus the identical local provenance check.
   HPC BoR's different manifest representation retains its adapter-specific
   attestation builder. Memory reporting and BoR channel slicing are shared.

2. Explicit process settings in runs/driver_settings.py.

   All four drivers capture a DriverSettings snapshot instead of injecting
   parameter names with globals().update(). Their internal reads use _SETTINGS.
   current_settings() returns independent dictionaries for manifests and spawned
   workers. Snapshots copy caller-owned values and are pickleable. Execution
   decorators now obtain configured controls through current_settings().

   Existing parameter scripts, configure()/run(), default loaders, static BoR
   JSON contracts, adjacent/explicit configuration loading and spawned-worker
   parameter dictionaries are retained. BoR configuration is validated before
   replacing the previous snapshot; a rejected configuration leaves it intact.

   Compatibility boundary: reads such as driver.GEOMETRY_UNITS still work via
   module __getattr__. The driver module's vars()/__dict__ no longer holds each
   configured parameter. Direct assignment to driver.GEOMETRY_UNITS is not a
   way to reconfigure the solver now; use configure(). Caller dictionary/list
   mutations after configure() no longer alter the captured run. A process
   still has one active configuration per driver module: this does not promise
   concurrent independent configurations within a single module/process.

3. Extract independent BoR helpers behind retained import names.

   bor/constraints.py: sparse pole/junction constraints and bounded matrix
   operations. bor/validation.py: direct-solver geometry and aspect validation.
   bor/storage.py: storage records and operator-storage estimates shared by
   previews and solve admission. All 19 moved function/class definitions have
   identical ASTs to the base. Every remaining solver function/class also has
   an identical AST. solver.py re-exports the moved names and storage records.
   Their defining __module__ changes, as expected after extraction; import
   locations used by current callers remain available.

4. Remove the unused UI _parse_mesh_n_token copy.

   geometry/validation.py retains the active implementation. No production
   repository caller of the UI copy was found. External consumers of that
   private UI helper would need to use the validation implementation.

5. Update GRIM's completeness contract in the same patch.

   GHOST_SENTINELS includes the five new mandatory modules. All 68 mapped GRIM
   imports still load and all 126 required files exist. Removing each new file
   in turn correctly rejects discovery, preventing a repeat of BC-01. Frozen
   local/HPC runtime bundles include all five files in actual driver runs.

Preserved and deliberately deferred
-----------------------------------
* Dense/Compressed, native/NumPy, 2D/BoR and material formulations remain.
* All eight DLL/SO libraries, four native C sources and native manifests remain
  byte-identical. No native recompilation was performed or required.
* 509 existing files outside the explicit change list remain byte-identical.
* The retained-unused legacy certification inspector stays for compatibility.
* Assembly/Line Expansion code is unchanged. Its known defects should be fixed
  before its large fields/workflow modules are restructured. This patch is not
  a repair or release signoff for those workflows.
* The large BoR solve implementations and 2D solver orchestration still warrant
  later, separately reviewed decomposition. This is the first bounded structural
  pass, not a claim that all backend complexity or duplication is eliminated.

User-visible implications
--------------------------
Normal GUI and parameter-script controls, file formats, numerical methods and
selected mesh policy are intended to behave as before. Programmatic clients
must use configure() to change driver settings; implicit mutation after capture
is intentionally prevented. Source fingerprints change with this refactor, so
old restart artifacts must not be combined with a new source inventory. Existing
provenance checks continue to enforce that boundary; start a new run when changing
the solver source. Raw GRIM archives are not claimed to be byte-identical across
versions because provenance/runtime metadata can differ. Numerical arrays are
compared independently below.

Reproduction

(BASE). PY is a Python environment with the dependencies above. Replace paths.
Tests write results beside their scripts. The integration/module-map scripts
temporarily rename files with finally-protected restoration; run them alone
against a checkout that no application process is using.

  BASE=/absolute/path/to/base-checkout
