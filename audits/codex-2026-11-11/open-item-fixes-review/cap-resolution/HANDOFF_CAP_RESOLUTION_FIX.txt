WHAT CHANGED

Only execution/options.py and execution/memory_budget.py change relative to
Claude's accepted implementation. At the outer public solver boundary:

1. Normalize arguments and resolve/validate execution options using the existing
   option resolver before enrolling the request in the memory ledger.
2. Query reservation_caps() under those resolved settings and use the tightest
   request/scheduler cap for admission. MemoryBudget.caps() delegates to that
   same helper, so admission and the live gates cannot disagree about sources.
3. Keep the memory scope alive through planning, the numerical solve and the
   bounded Compressed retry with ExitStack. Nested calls share the outer ledger.
4. Exclude admission queue time from execution_wall_seconds, preserving the
   meaning of numerical timing evidence used by the legacy adaptive policy.

Explicit ram_budget_gib=None still masks the environment cap; scheduler limits
still apply. Direct partial profiles retain their prior default semantics;
automatic partial profiles retain their existing environment merge. Invalid or
conflicting profiles reject before queueing. Cancellation and the exception for
callers already holding the BLAS lock remain; such callers must not wait while
a peer needs that lock to finish and release its memory reservation.

USER IMPACT AND REMAINING LIMITS

No GUI controls, profile fields or numerical thresholds change. Capped concurrent
requests now wait consistently regardless of where their effective cap came
from, instead of failing prematurely against a peer's temporary remainder.
Waiting for the full cap is still conservative and may serialize solves whose
actual needs are smaller. Uncapped requests needing more than a positive
remainder >=0.5 GiB can still be refused: forecast-aware queueing is not added.
The BLAS-lock-holder exception can also still refuse immediately. Existing live
physical/commit headroom gates remain authoritative. The new distribution also
includes Claude's bounded explicit-Compressed retry, as described previously.
